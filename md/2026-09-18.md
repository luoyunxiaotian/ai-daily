## 四、15 条精选 · 甲组：AI Coding（8 条）

### ① Anthropic 重做 Claude Code Projects：一个目标拆成多条并行线程，合上电脑仍在跑

09-17，Anthropic 正式推出 Projects 重大升级，把 AI 辅助开发从「单次对话」升级为「多线程自动化工作流」。核心是**「协调者 + 工作线程」双层架构**：用户在主聊天界面给出高层指令（如「把应用结账的 P75 延迟降下来」），Claude 充当参谋长把任务路由至多条独立线程，每条线程是一个**独立的 Claude Code 云端会话**，在各自的代码分支与仓库副本上执行，可自行开 PR、跑测试。官方称**这些线程在用户关闭笔记本电脑后仍会继续工作**。所有线程共享同一记忆池，Claude 会跨会话沉淀项目细节（如「发布日期改到周五」「某功能为何被废弃」）。冲突按标准合并冲突处理；单条线程还可再调用子代理、循环与工作流。目前以 Beta 向部分 Pro / Max 订阅用户开放（需使用云端会话），Team 与 Enterprise 稍后，本地执行「即将到来」。

- **值得关注**：这是继「自动驾驶模式设为 Claude Code 默认选项」之后的第二步——**先把默认执行权交给模型，再把任务调度权交给模型**。用户要做的事从「写代码」变成「描述想要什么」。但也带来一个结构性变化：**控制烧多少 token 的开关，正从用户手里转移到卖 token 的公司手里**（有评论形容为「让加油站控制你车上的油门」）。对准备 IPO 的 Anthropic 而言，更自主的智能体大概率意味着更高的 token 消耗。
- **来源**：Anthropic 官方公告 / 华尔街见闻（09-18 05:13）/ 网易（09-18 02:41）
- **时效**：✅ 24h 内｜**置信度**：已确认

### ② Claude Code 2.1.274：MCP 可靠性大修 + 会话自愈，agent 运行时走向「可观测」

09-18 发布。重点包括：**修复会话陷入「unexpected tool_use_id」400 错误无限重试的死循环**（损坏的 transcript 现在尽可能自愈，否则给出带 `/rewind` 提示的明确错误）；修复配置为 `http` 但只支持 legacy HTTP+SSE 的 MCP 服务器在首个请求返回 422/4xx 时连接失败；修复 Streamable HTTP MCP 工具调用约 5 分钟超时（即使已设置更长的 per-server 超时）；修复 MCP 服务器在未声明 `listChanged` 时发送 list-changed 通知后 prompts/resources 不刷新；修复 403 `insufficient_scope` 被误报为「登录过期」（现在会指出缺失权限并引导 `/mcp` 重新认证）。新增：`CLAUDE_CODE_MCP_STARTUP_WAIT_MS` 约束首个非交互轮次等待 MCP 连接的时长；`claude_code.managed_settings_resolved` OTel 事件；`enduser.sub`（IdP subject）进入网关遥测。hook 驱动的会话（如活跃的 `/goal`）在上下文溢出时改为压缩而非报「Prompt is too long」。

- **值得关注**：这一版的重心不是加功能，而是**把 agent 运行时从「能跑」修成「可诊断、可恢复、可计费」**。特别是 `managed_settings_resolved` 事件与 `enduser.sub` 进入遥测——**企业要落地 agent，第一道门槛从来不是能力，而是「出事之后能不能追溯到是谁、用了什么策略」**。MCP 的四个修复也说明 MCP 已经从演示阶段进入生产环境，早期协议兼容的粗糙面正在集中暴露。
- **来源**：Anthropic Release Notes（09-18）
- **时效**：✅ 24h 内｜**置信度**：已确认

### ③ 四大 AI 编程代理曝同一逻辑缺陷：「技能」自动更新机制可被劫持

09-18 01:48 报道，网络安全初创公司 Air 独家披露：**Anthropic Claude Code、OpenAI Codex、Google Gemini CLI、GitHub Copilot 四款主流 AI 编程代理存在相同逻辑缺陷**——其「技能（Skills）」自动更新机制**未校验内容变更**，攻击者可伪装同名的恶意更新绕过扫描，静默窃取企业代码或知识产权。该漏洞源于各厂商验证机制设计雷同，属于行业共性盲区。目前除 GitHub 外其余三家已修复；GitHub 称平台机制可阻断此类攻击，但未确认补丁状态。

- **值得关注**：这是本期最需要警惕的一条。过去两年「技能包 / 插件市场」是 AI Coding 生态增长最快的部分（GitHub Trending 长期被 skills 类仓库刷屏），但**供应链安全的成熟度远远落后于分发速度**。四家实现出**同一个**逻辑缺陷，说明这不是某家的疏忽，而是整个范式在「如何信任一个会自我更新的能力包」上还没有答案。与本期第 ② 条的 MCP 可靠性修复放在一起看：**agent 生态正在同时补「运行时可靠性」和「供应链安全」两块短板**。
- **来源**：金融界（09-18 01:48）引述 Air 研究
- **时效**：✅ 24h 内｜**置信度**：大概率（单家安全公司披露，厂商未全部公开确认）

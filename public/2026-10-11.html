A1 · Anthropic 把「一个智能体」升级为「一支舰队」：Managed Agents 动态工作流开放公测，单任务最多并行 1000 个子智能体 已确认

  • 事件：10-09 Anthropic 在 Claude Managed Agents 内推出 dynamic workflows 公开测试版。机制变化：此前 Managed Agents 只能顺序委派子智能体，且每个结果都要回流到主智能体的上下文窗口；现在主智能体自己写一个工作流程序（workflow program），由服务端在后台分阶段执行，主智能体只做一次任务规划，fan-out、分阶段执行、结果聚合、失败捕获全部由程序生成的代码接管，主智能体可被释放去继续对话。配置方式：multiagent.type = "multiagent_20261001"（默认同时启用 workflows 与 subagents），API 需带 anthropic-beta: managed-agents-2026-04-01 头。规模：每 run 最多 1000 个 agent，Anthropic 文档口径如此，第三方（WesRoth）实测并发上限为 64。worker 分两类：inline worker（由工作流现写 system prompt，继承主智能体模型与工具子集及其权限策略）与 predefined worker（独立模型/工具/技能，工作流因此可以在同一 run 内混用不同模型）；subagents 与 workflows 的 predefined 列表各最多 20 个；普通 subagent 子线程上限 25。官方基准（核心数据）：在一个 11.6 万行、内置 70 处隐藏 bug 的代码库上，单智能体每次只能找出 14–27 个，动态工作流三次运行稳定找出 66 个（约 2.4 倍召回）。原理是把代码切片、给每个子智能体独立上下文扫描，再加一道核验阶段以绕开单智能体的上下文容量上限。官方建议场景：仓库级 bug hunt、迁移、安全审计、性能与架构分析、数百份文档的批量审阅。
